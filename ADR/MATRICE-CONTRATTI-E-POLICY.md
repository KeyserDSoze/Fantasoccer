# Matrice degli adattatori, operazioni e policy

La compatibilità dei vecchi URL/JSON non è richiesta. In SQL gli endpoint automatici RepositoryFramework non sono registrati: anche `Query`, `Count`, `Batch`, `Bootstrap`, `Insert`, `Update`, `Delete` generici rimangono indisponibili. Le letture/list/query e scritture approvate sono sostituite dalle operazioni esplicite sotto. Non esiste un repository EF generico sostitutivo.

| Superficie legacy / factory | Sostituzione SQL | Policy e hook applicativi preservati/rafforzati |
| --- | --- | --- |
| AppIdentity Get / profilo / selezioni | `/api/accounts`, `/api/workspace/account` | Account SQL abilitato; login esterno verificato; selezioni gruppo/lega/anno coerenti; nessun ruolo globale modificabile dal profilo |
| Group CRUD / membri / basket / annualità | `/api/groups`, `/api/workspace/groups` | Membership corrente per gruppo; manager per amministrazione; amministratore globale fidato per nuovi gruppi/inviti; revisioni, tutela ultimo responsabile, proprietà e partecipazioni tramite FK composte |
| Settings Get/Update e SettingsController | `/api/accounts/settings`, `/api/team-assets` | Preferenze del proprio account; nomi/loghi della squadra autorizzata; versioni Blob immutabili e riferimento salvato dopo verifica |
| Team, Team/day, Team/opening Get/Save | `/api/teams/roster`, `/api/teams/formation`, `/api/competitions/.../games/.../formation` | Membership, proprietà/co-proprietà o modalità amministrativa autorizzata; giorno/stagione/partita coerenti; prezzi/fondi solo server; ID/posizioni/versione giorno e origine; checker modulo, deadline e limite cambi live; storico e finanze mantenuti |
| Game Get / SaveTeam / SwitchPlayers / Optimal | `/api/competitions/{group}/{league}/{year}/games`, `/optimal-formation` | Stessi servizi e motori caratterizzati; snapshot storico, non rosa odierna inventata; risultati salvati autorevoli, anteprime marcate; nessuna persistenza da GET |
| OpeningCompetition Prepare / Team | `/api/competitions/.../opening` | Lettura distinta da preparazione POST; squadra N-1, lega/giocatori N; scope lega principale e giornate configurate; premi preservati e accreditati nel flusso autorizzato |
| Calendar, Rank, Rank/day Get / query | `/api/competitions/.../calendar`, `/rank?day=` | Membership della competizione, gruppo/lega/anno verificati; stage/turno/giornata distinti; nessuna scrittura classifica generica dal browser |
| LeagueManager Create/Recalculate | `/calendar/generate`, `/recalculate` sotto competizione | Responsabile del gruppo; versione/conferma per sostituzione, rifiuto calendario con risultati; completezza voti ufficiali e transazione di risultati/snapshot/classifiche; runner automatico solo per risultati assenti |
| RealPlayers / RealCalendar / RealRank / votes / chances / stats | `/api/football` | Dati condivisi leggibili da account abilitati; refresh/rinvii solo global admin fidato; parser separati dai writer; parse vuote/troncate rifiutate; timestamp Roma/UTC espliciti; nessuna duplicazione di catalogo per gruppo |
| RealPlayers/random | `/api/competitions/.../auction-order` | Membership; randomizzazione per manager con versione; ordine/visibilità per lega, non alterazioni della visibilità del catalogo globale |
| Market Get/Create/Accept/Reject/Approve/Deny/Cancel | `/api/competitions/.../market` | Stagione corrente, squadre partecipanti, proprietà corrente; accettazione venditore; un voto per squadra anche con co-owner; quorum corrente, budget/prezzi server, transazione su entrambe le rose e outbox; preservazione righe vendute |
| AuctionController / AuctionHub / MCP auction | `/api/auctions`, `/auctionhub` relazionale | Servizio condiviso; banditore/admin e proprietario verificati ogni comando; versione asta/rosa, timer, budget e limiti ruolo; ordine futuro privato; presenze distinte dall'audit legacy; notifiche solo ID/versione, rilettura autorizzata |
| Rank credits / premio iniziale | `/api/teams/credits/confirm-rank-checkpoint` + asta | Conferma con saldo/versione attesi e audit per dati legacy non ricostruibili; accrediti incrementali separati dai conguagli mercato; nessuna sovrascrittura del saldo importato |
| LiveGroup Get | `/api/groups/{group}/live` | Proiezione SQL per gruppo/anno; nessuna cache singleton cross-account; archivio legacy conservato ma non usato come fallback |
| HallOfFame Get / job refresh | `/api/groups/{group}/leagues/{league}/hall-of-fame` | Lettura membro; refresh/conferma baseline manager; delta annuali, record standalone e totali per proprietario conservati; rifiuto di identità/contatori ambigui |
| CardController CRUD / immagini | `/api/cards` | Lettura autenticata; modifiche solo amministrazione globale fidata; condizioni e presenza false/zero/vuoto mantenute; versioni; archiviazione invece di cancellare storico/immagini; librerie non-default non esposte senza conferma |
| NewsWrapper / NewsJob | `/api/groups/{group}/news/{year}/{day}` | Membro per leggere; manager lega per generare; dati salvati completi, CAS, lock di generazione, niente email nei facts; generazione disabilitata per default |
| TeamWithAi / TeamHelperJob | `/api/groups/{group}/teams/{team}/advice/{year}/{day}` | Proprietari della squadra e destinatario personale per account (co-owner separati), non un generico membro o amministratore globale; prompt del chiamante, CAS della rosa; nessuna modifica formazione/economia |
| PushNotificationController | `/api/push-notifications` | Proprio account, patch parziale e opt-out rispettati; endpoint globale con proof privata ruotata per trasferimenti; pulizia provider CAS; quarantena legacy solo globale verificato |
| PushNotificationSent / invio job | producer/outbox/dispatcher SQL | Checkpoint e outbox nella stessa transazione; lease, TTL, backoff/limiti/ricevute, preferenze/ownership correnti; provider allowlist senza redirect; import e GET non inviano |
| PlayerImage Reload/ReloadTeam / job | `/api/player-images` | Catalogo e roster SQL, UUID; membership per singola foto, proprietari/stagione corrente per batch; fonte ufficiale e Blob key condivisi, timeout ed errori parziali |
| FantasoccerLog Table / query | `/api/operations/logs` | Global admin fidato; archivio tipizzato originale privato, elenco/statistiche limitati e redatti; timestamp ignoti restano null |
| Vecchi background job | `/api/operations/jobs`, worker SQL | Global admin per esecuzione manuale, nessuna impersonazione nei job; stessi servizi; lease/fencing e ricevute; configurazione locale disabilitata finché non si attiva esplicitamente |
| OAuthDocument / MCP client management | Store OAuth SQL e route protocollo esistenti | Audience/risorsa MCP, CAS/retention, account corrente, revoca; query token limitati al solo hub e token MCP esclusi dall'hub; chiavi/certificati conservati separatamente |
| Ping / Context / health / discovery | Route pubbliche/protette esistenti | Health/discovery non rivelano dati del gioco; contesto protetto, stagione indice; nessun bypass login locale o super-admin demo |

## Verifiche trasversali

- I controller SQL sono in una whitelist esplicita sia nel runtime sia nel catalogo MCP. Il facade MCP continua a eseguire filtri/policy e chiama gli stessi servizi; il guard non accede ai repository legacy per questi controller.
- I test HTTP/SignalR coprono cambi di ruolo, account esterni, scope cross-group/lega/anno, contraffazione prezzi/stati/ID, versioni stale, co-owner concorrenti e rollback forzato durante un trasferimento.
- Gli automatismi non azzerano formazioni inviate e non riscrivono giornate iniziate/storiche. Import, schema startup e rete/provider sono tre operazioni distinte.
- Nessun contratto attivo del frontend usa `Raw`, decoder di abbreviazioni o `RepositoryServices`; la dipendenza npm è rimossa. I converter legacy sono confinati agli import e ai test di regressione.
- Restano verifiche sui dati/configurazioni reali (issuer, chiavi, VAPID, scope/checkpoint non ricostruibili) e accettazione UI/login, non endpoint Blob lasciati attivi per aggirarle.
